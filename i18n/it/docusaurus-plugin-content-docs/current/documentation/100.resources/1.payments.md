# Comprendere i pagamenti

### How a transaction works behind the scenes
Typically, payment gateways adopt a two step process for completing a payment. First step is authorization and it occurs after customer enters their payment method data. It's checked that there are sufficient funds and the amount is held pending. Second step is transaction catpure, where funds are withdrawn from the customer account, processed and transferred to the merchant account.

:::warning
Payment gateways not supporting two-step process are all voucher payment gateways, Satispay and Adyen.
:::

In Voucherly, to determine the state of a transaction, there is the `state` field.

### Transaction status

| Status | Description |
|--|--|
| **Requested** | A new transaction object has been created, but not already paid.  |
| **Paid** | Transaction has been authorized. The funds are blocked until confirmation takes place ([Confirm Payment API]("/api/webapi/confirm-payment")) or until the time interval defined by configuration with the payment gateway expires.  |
| **Confirmed** | Transaction has been captured. The funds previously blocked have been transferred to the merchant account. |
| **Refunded** | Transaction previously in `CONFIRMED` status has been fully refunded. |
| **Dropped** | Transactions has been released. |
| **Cancelled** | Transaction previously in `PAID` status has been cancelled. Funds have been unlocked. |
| **Failed** | Payment gateway failed to pay the transaction. |
| **Voided** | A transaction previously `PAID` has been voided due to an error or customer canceled payment. |
| **Expired** | |
| **ImpossibleRefund** | |


### Payment status
Payment also has a `status` field that depends on the status of its transactions.

| Status | Description |
|--|--|
| **Requested** | A payment has been created but has no transactions.  |
| **Paid** | Customer has successfully completed the checkout. There is at least one transaction `PAID` that has to be completed. |
| **Confirmed** | Payment was successful and all transactions were confirmed. |
| **Refunded** | All transactions have been refunded.  |
| **Cancelled** | All transactions have been cancelled. |
| **Voided** | All transactions have been voided.  |
| **Expired** | |

### Auto confirm
From the [Dashboard](https://dashboard.voucherly.it/) it's possible to enable Auto Confirm for the merchant. If active, all transactions will be automatically confirmed at the end of a payment. In this way, it will not be necessary to call [Confirm Payment API](/api/webapi/confirm-payment).

### Confirm a payment
:::warning
Does not apply if auto confirm is enabled.
:::

In [Accepting Payment](/documentation/use-cases/payment) use case, you always have to confirm the payment. However in [Charge Wallet](/documentation/use-cases/charge-wallet) use case, you don't have to, as transactions are confirmed istantly.

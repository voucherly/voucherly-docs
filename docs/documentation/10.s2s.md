# Server-to-Server (S2S) Communication

Server-to-Server (S2S) communication occurs between Voucherly's server and the merchant's server at the end of a checkout phase to notify the merchant about the payment result.

:::info
It is recommended to set up an S2S endpoint on the merchant's server to avoid losing the payment result if the customer closes their browser before being redirected to the merchant's `redirectOkUrl` or `redirectKoUrl`.
:::

:::warning
Since the S2S call is sent every time a user completes a checkout flow for a payment, there may be cases where two requests are received. This can happen if the payment initiated by the merchant is in `Payment` mode, Wallet is enabled, and the customer decides to charge the wallet during the payment process. Voucherly handles the wallet charge as a separate payment (as detailed in the [Charge Wallet](use-cases/charge-wallet) use case), linking it to the original payment using `ParentPaymentId` (the ID of the merchant-initiated payment) and assigning it the `Wallet` mode.
:::

## Integration

The merchant's endpoint URL must be specified when creating the payment via the [Create Payment API](/api/webapi/create-payment).

When the customer leaves the Voucherly Checkout page, whether the payment is successful or not, Voucherly attempts to contact the merchant's server before redirecting the customer to the merchant's website.

Merchants need to configure an endpoint that accepts a POST request with a JSON body containing a subset of the Payment properties.

### Request Format

- **Id** *(string)*  
  Unique identifier of the payment.  
- **Tenant** *(string)*  
  Indicates the environment: *live* or *sand*.  
- **Mode** *(string)*  
  The mode of the payment: `Payment` or `Wallet`.  
- **ReferenceId** *(string)*  
  A unique string to reference the payment (e.g., customer ID, cart ID) for reconciliation with internal systems.  
- **MerchantId** *(string)*  
  The merchant's identifier.  
- **CustomerId** *(string)*  
  The ID of the customer for this payment.  
- **TotalAmount** *(long)*  
  The total amount before discounts.  
- **DiscountAmount** *(long)*  
  The discounted amount.  
- **FinalAmount** *(long)*  
  The final amount, calculated as `TotalAmount` - `DiscountAmount`.  
- **PaidAmount** *(long)*  
  The amount actually paid.  
- **PaidVoucherAmount** *(long)*  
  The portion of the payment paid using vouchers.  
- **Amount** *(long)*  
  The net amount of this payment.  
- **Status** *(string)*  
  The current status of the payment: `Requested`, `Paid`, `Confirmed`, `Refunded`, `Cancelled`, `Voided`, or `Expired`.

:::info
Since the merchant S2S endpoint does not require any authentication setup, it is recommended to call the [Get Payment API](/api/webapi/get-payment) to validate that the request originates from Voucherly. This API provides all the necessary information about the payment.
:::

#### Response
The merchant server must respond with an HTTP `200 OK` status code and a JSON body in the following format:

- **Ok** *(bool)*  
  Indicates whether the S2S request was successfully processed by the merchant server.
- **OrderId** *(string?)*  
  The unique identifier of the order in the merchant's system.

```json [S2S Expected Response]
{
    "ok": true,
    "orderId": "eb8f57f8-241b-4142-b7b0-d308d724541a"
}

```

:::warning
If the merchant's server responds with an HTTP status code other than `2xx`, or if the `Ok` field in the response body is `false`, Voucherly will retry the call up to three times. If the issue persists, the payment will be cancelled, and all transactions will be refunded.
:::

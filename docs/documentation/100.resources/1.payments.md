# Understanding Payments

### How a Transaction Works Behind the Scenes

Typically, payment gateways follow a two-step process to complete a payment. The first step is **authorization**, which occurs after the customer enters their payment method details. At this stage, funds are checked for availability and held pending. The second step is **transaction capture**, where the funds are withdrawn from the customer’s account, processed, and transferred to the merchant’s account.

:::warning
Payment gateways that do not support the two-step process include all voucher payment gateways, Satispay, and Adyen.
:::

In Voucherly, the state of a transaction is determined by the `state` field.

### Transaction Statuses

| Status           | Description                                                                                             |
|-------------------|---------------------------------------------------------------------------------------------------------|
| **Requested**     | A new transaction object has been created but has not yet been paid.                                   |
| **Paid**          | The transaction has been authorized. Funds are blocked until confirmation occurs ([Confirm Payment API]("/api/webapi/confirm-payment")) or the time interval defined by the payment gateway configuration expires. |
| **Confirmed**     | The transaction has been captured. Funds previously blocked have been transferred to the merchant’s account. |
| **Refunded**      | A transaction in the `CONFIRMED` status has been fully refunded.                                       |
| **Dropped**       | The transaction has been released.                                                                    |
| **Cancelled**     | A transaction in the `PAID` status has been cancelled, unlocking the funds.                           |
| **Failed**        | The payment gateway failed to process the transaction.                                                |
| **Voided**        | A `PAID` transaction has been voided due to an error or a customer cancelling the payment.             |
| **Expired**       | The transaction has expired.                                                                          |
| **ImpossibleRefund** | A refund could not be processed for the transaction.                                               |

### Payment Statuses

Payments have a `status` field that reflects the statuses of their transactions.

| Status           | Description                                                                                             |
|-------------------|---------------------------------------------------------------------------------------------------------|
| **Requested**     | A payment has been created but no transactions exist yet.                                              |
| **Paid**          | The customer has successfully completed the checkout. At least one transaction is in the `PAID` state and awaits completion. |
| **Confirmed**     | The payment was successful, and all transactions have been confirmed.                                  |
| **Refunded**      | All transactions have been refunded.                                                                   |
| **Cancelled**     | All transactions have been cancelled.                                                                  |
| **Voided**        | All transactions have been voided.                                                                     |
| **Expired**       | The payment has expired.                                                                               |

### Auto Confirm

From the [Dashboard](https://dashboard.voucherly.it/), merchants can enable the Auto Confirm feature. When enabled, all transactions are automatically confirmed at the end of a payment, eliminating the need to call the [Confirm Payment API](/api/webapi/confirm-payment).

### Confirming a Payment

:::warning
This does not apply if Auto Confirm is enabled.
:::

In the [Accepting Payment](/documentation/use-cases/payment) use case, you must confirm the payment manually. However, in the [Charge Wallet](/documentation/use-cases/charge-wallet) use case, transactions are confirmed instantly, so no manual confirmation is required.

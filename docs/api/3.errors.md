# Errors

Voucherly uses conventional HTTP response codes to indicate the success or failure of an API request. In general: Codes in the  `2xx`  range indicate success. Codes in the  `4xx`  range indicate an error that failed given the information provided (e.g., a required parameter was omitted, a charge failed, etc.). Codes in the  `5xx`  range indicate an error with Voucherly's servers (these are rare).

Errors are returned as [problem details (RFC 7807)](https://www.rfc-editor.org/rfc/rfc7807). Please referer to official documentation.
Additional attribute can be returned for `400`  errors. 


::method-area
#description
:method-attributes
::method-list
- ::method-list-item{name="Type" validation="string"}
  URI reference of the RFC to identify the problem types
  ::
- ::method-list-item{name="Title" validation="string"}
  Short human readable problem summary
  ::
- ::method-list-item{name="Status" validation="int"}
  Http status code
  ::
- ::method-list-item{name="Details" validation="string"}
 A human readable explanation for what exactly happened
  ::

#example
::code-group
```json [404 Not Found]
{
    "type": "https://tools.ietf.org/html/rfc7231#section-6.5.4",
    "title": "Payment was not found.",
    "status": 404,
    "detail": "Entity \"Payment\" (sbpay-OJKgojAPRGd) was not found."
}
```
```json [400 Bad request]
{
    "type": "https://tools.ietf.org/html/rfc7231#section-6.5.1",
    "title": "ReferenceId is duplicated.",
    "status": 400,
    "detail": "You provided 'eb8f57f8-241b-4142-b7b0-d308d724541f' as ReferenceId. But there is an already existing payment.",
    "code": "PAYMENT_DUPLICATED",
    "parameter": "ReferenceId"
}
```

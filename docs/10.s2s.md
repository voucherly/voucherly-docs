# Server to Server
Server-to-Server (S2S) involves communication between Voucherly server and the merchant's server at the end of a checkout phase to notify the merchant of the result of a payment.

:::info
It's reccomended to set up a S2S endpoint on the merchant server to avoid losing the result of a payment if the customer closes the browser before the redirect to the merchant `RedirectSuccessUrl` or `RedirectErrorUrl`.
:::

:::warning
Since S2S is sent each time the user finishes a checkout flow for a payment, in some cases expect to receive 2 requests: this could happen if the payment created by the merchant has `Mode` `Payment`, Wallet is enabled and customer decides to charge the wallet during the payment. Voucherly handles the wallet charge as a new payment (as described in the [Charge Wallet](use-cases/charge-wallet) use case), with `ParentPaymentId` the ID of the payment created by the merchant and `Mode` `Wallet`.
:::


## Integration
The merchant endpoint url has to be specified when creating the payment through the [Create Payment API](/api/payments/create_payment).

When customer leaves Voucherly Checkout page, whether the payment was successful or not, Voucherly attempts to contact the merchant's server before redirecting the user to the merchant website.

Merchant has to set up an endpoint that accepts a POST call with body in Json contaning a subset of Payment properties.

#### Request
 - **Id** *(string)*
Unique identifier of the payment.
 - **ReferenceId** *(string)*
A unique string to reference the Payment. This can be a customer ID, a cart ID, or similar, and can be used to reconcile the Payment with your internal systems.
 - **ParentPaymentId** *(string)*
The ID of the parent payment. A payment has a parent payment typically when this is of `Mode` `WALLET` and this is the wallet charge inside a payment flow.
 - **MerchantId** *(string)*
Merchant identifier.
 - **CustomerId** *(string)*
The ID of the customer of this Payment.
 - **CustomerFirstName** *(string)*
The first name of the customer of this Payment.
 - **CustomerLastName** *(string)*
The last name of the customer of this Payment.
 - **CustomerEmail** *(string)*
The email of the customer of this Payment.
 - **Culture** *(string)*
Culture of the payment.
 - **TotalAmount** *(long)*
The amount without discounts of this Payment.
 - **DiscountAmount** *(long)*
The amount discounted of this Payment.
 - **FinalAmount** *(long)*
The amount of this Payment. It's equal to `TotalAmount` - `DiscountAmount`.
 - **PaidAmount** *(long)*
The amount paid of this Payment.
 - **PaidVoucherAmount** *(long)*
The amount paid with vouchers of this Payment.
 - **Amount** *(long)*
Actual amount of this Payment.
 - **Status** *(string)*
Status of this Payment. Can be `Requested`, `Paid`, `Confirmed`, `Refunded`, `Cancelled`, `Voided` or `Expired`.
 - **Mode** *(string)*
Mode of this Payment. Can be `Payment` or `Wallet`.

:::info
Since merchant S2S endpoint does not have to prepare any type of authentication, to validate that the request really comes from Voucherly, it is reccomended to call the [Get Payment API](/api/payments/get-payment) to obtain all the information about the payment.
:::

#### Response
Merchant server has to responde with a `200 OK` http status code and a json body with the following format.

 - **IsSuccess** *(bool)*
 Is the result of processing the S2S by the merchant server.
 - **OrderId** *(string?)*
 The ID of the order on the merchant systems.

```json [S2S expected response]
{
    "isSuccess": true,
    "orderId": "eb8f57f8-241b-4142-b7b0-d308d724541a"
}
```

:::warning
In case that merchant's server answers with a http status code different from `2xx` or in the response body `IsSuccess` is false, Voucherly retries the call for a maximum of 3 times. If the error persists, the payment will be cancelled and all transactions refunded.
:::

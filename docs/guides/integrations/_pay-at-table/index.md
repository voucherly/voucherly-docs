# Pay at Table

Use Voucherly Pay at Table feature to allow customers to independently pay their bill, integrated with the cashier system.

:::warning Requirements
- In the dashboard create tables of the store, ...
- You must set up an authentication system (referred to below as the Identity Provider) that enables the customer to authenticate, so that Voucherly can receive their information.
- Provide to Voucherly the RSA public key to be used to verify the signature. 
:::


## Quick Guide

Let’s walk through a simple example of integrating the flow.

:::info
This integration is designed to dynamically generate a QR code, enabling users to effortlessly scan it with their mobile devices and complete the payment process seamlessly.
:::

### 1. Setup the Identity Provider

Voucherly expects the merchant to expose two endpoints for handling customer authentication within the merchant’s systems.

#### Authentication Endpoint

The first endpoint is invoked when the customer scans a QR code. This request will include a query parameter named `returnUrl`, which specifies the Voucherly endpoint to redirect the user to once the authentication flow is completed.

When the customer lands on this endpoint, the merchant is responsible for verifying the user’s identity.

* If the user is not authenticated, the merchant may allow the customer to continue as a guest by redirecting them back to the provided `returnUrl` without appending any additional query parameters.

* If the user is successfully authenticated, the merchant must append the following query string parameters to the `returnUrl`:
    * **customerId** *(required)*: unique customer identifier within the merchant's system
    * **email**: customer's email address
    * **friendlyName**: a display-friendly name for the customer
    * **firstName**: customer firstname
    * **lastName**: customer lastname
    * **timestamp** Unix timestamp of the redirect, calculated by the merchant system in seconds
    * **signature**: digital signature generated by the merchant from the provided parameters (see next section)

#### Signature calculation

The `signature` parameter is used by Voucherly to ensure integrity and authenticity of the request. You must compute it using asymmetric RSA encryption with 2048-bit keys in PKCS#8 format.

1. Concatenate the following parameters in the exact order:

    ```
    customerId + email + friendlyName + firstName + lastName + timestamp
    ```

2. Compute the SHA-256 hash of the resulting string.
3. Sign the hash padded PKCS#1 v1.5 using RSA private key encryption.
4. Encode the resulting signature in Base64 and append it as the `signature` query parameter in the redirect URL.

    <Tabs>

    <TabItem value="csharp" label=".NET">

    ```csharp
    var concatenation = new StringBuilder()
        .Append(customerId)
        .Append(email)
        .Append(friendlyName)
        .Append(firstName)
        .Append(lastName)
        .Append(timestamp)
        .ToString();

    var dataBytes = Encoding.UTF8.GetBytes(concatenation);

    var privateKey = ReadPrivateKeyPem();

    using var rsa = RSA.Create();
    rsa.ImportFromPem(privateKey);

    var signature = rsa.SignData(dataBytes, HashAlgorithmName.SHA256, RSASignaturePadding.Pkcs1);
    ```

#### Logout endpoint

The second endpoint must be exposed to handle logout requests initiated by Voucherly, allowing the merchant to properly terminate the customer’s session in their system.
